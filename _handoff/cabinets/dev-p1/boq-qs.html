BOQ + QS · Bill of Quantities & Quantity Surveyor

The construction-industry ledger. Every project has a BOQ: ~142 line items grouped into Work Packages (WP-01 Earthworks, WP-02 Concrete, WP-03 Steel, WP-04 Finishes, etc.). Each line: code · description · planned qty · unit · planned rate · actual qty · actual rate · variance. QS approves variances before they roll up into project P&L. The "anomaly" rows we showed in Mgmt Finance trace back here — every utility +21% or marble +18% has a BOQ line.

Two cabinets, one cabinet

"BOQ" is the ledger; "QS" is the role. Combined here because the only user of BOQ data at scale is the QS. PM glances at totals (via Project detail KPIs). CFO reads aggregates (via CFO console). QS lives here all day. Big-table cabinet — virtualized rows, sticky header, cursor pagination from template 03.

Flow · Import + reconcile

BOQ import · 3-step wizard

QS uploads new BOQ revision (Excel/CSV from QS firm) → maps columns → reconciles against current. Diff-view shows added/changed/removed lines before committing. Same flow handles initial-import (new project) and revision (re-quoted scope).

Step 1 · Upload
CSV / XLSX / XLS · drag-drop · auto-detects WP grouping · validates row count (warn if >200 or <30 — likely wrong file)
Step 2 · Map columns
Auto-map known headers (code, description, qty, unit, rate). User confirms / overrides. Required fields validated. Unmapped columns dropped.
Step 3 · Reconcile
Diff against current BOQ (if revision): added lines green, removed red, changed yellow with old→new shown. Click row to see line history. Confirm reconciliation creates new BOQ revision with delta link to previous (audit-friendly).
Versioning
BOQs are versioned. Each line keeps history. Snapshot taken on every reconcile; diffs computed from snapshots, not from row mutations.
