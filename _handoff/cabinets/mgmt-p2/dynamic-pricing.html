06—Implementation

Engine, agents, schema

Pricing engine — order of operations
1. Pull base rate from villas.base_rate
2. Apply season multipliers (priority 4)
3. Apply algo (demand + comp + LY) → recommendation
4. Apply day-of-week / occupancy-tier rules
5. Apply event overrides (event tag match)
6. Apply manual pins (curve handles)
7. Clamp to floor/ceiling
8. Write to rate_cells.amount with source attribution
Each step's contribution is stored as a delta in rate_cell_audit so the UI can show "+22% weekend lift + +15% occupancy boost = …".

Critical UX rules
1. Active line on the curve ALWAYS reflects what's currently in rate_cells. No "preview mode" that diverges from reality.
2. Pinned overrides survive algo runs. Algo runs NEVER overwrite pinned values.
3. Pushing to Channels happens explicitly via the button — auto-push only fires for pinned overrides created >30d in the past (assumed validated).
4. Comp scraper failures degrade gracefully — show last-known with a "stale 36h" badge, don't hide the panel.
5. Rule reordering is a Drag op via @dnd-kit; saves on drop with an audit entry.
