AI agent — catalog & detail

Hybrid pattern. The cabinet route shows a catalog of agents. Each agent has a detail page with transcript + structured outputs + run history. Same skeleton for Mgmt agents (Concierge, Statement preparer, Daily digest) and Dev agents (QS cost analyst, Procurement matcher, Site reports digest).

List + detail•~30 agents total

Why hybrid (not co-pilot panel)

Earlier consideration: agents as a sidebar co-pilot embedded in each cabinet. Rejected because (a) the agent inventory grows to ~30 across Mgmt + Dev, sidebar wouldn't scale; (b) operators want to see runs they didn't trigger — daily digests, scheduled prepares; (c) agent outputs are first-class records (Statements ARE agent outputs), they deserve detail pages and URLs.

Spec

Anatomy

List route
/dashboard/ai (Mgmt) · /development-os/ai-agents (Dev). Page header + category chips + 3-column card grid. Cards 240–280px tall, hover lifts.
Detail route
/dashboard/ai/[agent-code] · /development-os/ai-agents/[agent-code]. Page header + 2-column body (transcript left, sidebar right) + composer.
Output sub-route
/dashboard/ai/[agent-code]/outputs/[output-code] — direct-link to a specific run's structured output. Renders just the structured-output card full-page with download buttons.
Transcript message
Three actor types: user (square avatar), agent (gradient mint→accent), tool (small grey square with ▶). Tool calls use mono font + paper background. Max 88% width.
Confidence + routing
Every agent message shows confidence %. Below threshold → routed-to-human badge with reason (revenue-impact, sensitive-content, novel-pattern). Reason chip uses warn tone.
Composer
Bottom-pinned textarea. Min 64px. Tools menu + Run button bottom-right. ⌘+Enter shortcut. Runs against staging env by default; toggle for prod.
Right sidebar cards
Output summary · Recent runs (last 7) · Configuration. All three present on every agent, content varies by agent type. 360px wide.
Live indicator
.pulse-dot ok when agent has run within last 5 min. .pulse-dot accent when actively in a run right now. Plain text "Scheduled · 06:00" for scheduled agents.
Empty state
New agent, no runs yet: use empty-state primitive (02) variant first-run with "Run first test" CTA pointing at composer.
For Claude Code

Where this lands

Catalog page
src/app/(dashboard)/dashboard/ai/page.tsx (already exists — refactor to use new <AgentCatalog>). Dev sister: src/app/(development-app)/development-os/ai-agents/page.tsx.
Detail page
src/app/(dashboard)/dashboard/ai/[agentCode]/page.tsx · sister Dev route. Use generateStaticParams on the list of agent codes from src/features/ai-agents/registry.ts.
Output sub-route
src/app/(dashboard)/dashboard/ai/[agentCode]/outputs/[outputCode]/page.tsx. Statement = special-case output that ALSO lives at finance/statements/[id] — both URLs resolve to the same data; statement route gets the detail-page treatment (template 05), output route gets a runtime view + download.
Components
src/components/ai-agents/agent-card.tsx, agent-transcript.tsx, agent-message.tsx (polymorphic on actor kind), agent-composer.tsx, agent-output-card.tsx, agent-runs-list.tsx, agent-config-card.tsx.
CSS
New section in src/styles/components.css. [data-product] .agent-card, .transcript, .msg, .output, .composer.
Streaming
Transcript component must handle streamed token deltas — use existing useAgentStream hook from src/features/ai-agents/use-stream.ts. Show typing indicator (3 dots) on agent message bubble while streaming.
Routing-to-human
When confidence below threshold, agent emits a routed message with reason. UI renders the warn-tinted info block; clicking the linked operator name opens a route-to-inbox modal (uses template 06 form-md).
