Page templates · 05

Detail page — modular

Not a single layout. A menu of 8 building blocks; each detail screen in 2.2 picks the subset it needs. Booking detail uses 6, Statement detail uses 3, Owner detail uses 5. The template defines spacing, anatomy, and behavior contracts so any assembly looks consistent.

The promise

Every record-detail screen in Arconique uses this template. The 8 bricks are the only shapes. If you need a 9th, it goes into the design system first (this template gets a new section), not into a one-off page. This is what keeps Bookings, Statements, Owners, Villas, Projects, Buyers, Investors, Vendors all visually coherent without re-deciding layout for each.

Spec

Layout & behavior contracts

Page layout
Main column flex-grows. Optional side panel = 300px fixed right column. Sticky action bar = full-width bottom. Tabs sit below header, span full width.
Header height
~110px (24px top pad + breadcrumb + h1 + 8px gap + meta line + 18px bottom pad). H1 = 34px display font.
Tabs
14×16px padding per tab, 13.5px Inter. On-state = bottom-border accent + 500 weight. Count badge inside tab matches dataset (e.g. "Activity 14").
Side panel
300px fixed. Background = var(--cream-warm) / var(--bg-2). Cards inside are paper-bg + 12px radius. Sticky at top when main scrolls.
Sticky action bar
~64px tall. Shows only when form is dirty OR record requires approval. Shadow = soft upward (0 -8px 24px -16px rgba(20,32,28,0.2)). Pad: 14px 28px.
Inline edit
Click field → outline appears (accent 2px) + becomes input. Tab/Enter to save individual field. Esc to revert. Aggregates to "N unsaved" in action bar.
Activity feed
Vertical line + 8px dots. Dot color matches event type (accent/ok/warn/neutral). Each entry: meta (mono uppercase) + what (Inter, bold names italic emphasis).
Related records
3-up card grid by default. Sits below main content with breathing room. Use grid-template-columns: 1fr for single-item display (Owner's only villa).
Approval flow
If record needs sign-off (e.g. draft statement), sticky bar shows even without dirty fields. "1 sign-off required" + Approve CTA.
Empty tabs
If a tab has 0 items, count badge hides. If user opens it, use empty-state primitive (02). Don't disable the tab.
For Claude Code

Where this lands

New directory
src/components/dashboard/detail/ — holds all 8 brick components plus the page layout shell.
Files
detail-page.tsx (shell), detail-header.tsx, detail-tabs.tsx, detail-side.tsx, detail-related.tsx, detail-activity.tsx, detail-actionbar.tsx. Inline edit lives in inline-edit.tsx. Main panel is just children — no wrapper needed.
Composition
Page is composed in each route file: 
<DetailPage>
  <DetailHeader … />
  <DetailTabs tabs={…} />
  <div className="main-and-side">
    <main>{tabContent}</main>
    <DetailSide sections={…} />
  </div>
  <DetailRelated items={…} />
  <DetailActionBar dirty={…} />
</DetailPage>
CSS
New section in src/styles/components.css. All classes scoped [data-product] as established by Phase 2.0.
State (dirty)
New useDetailFormState hook tracks per-field dirty status. Returns { isDirty, dirtyFields, save, discard }. Action bar reads from this; sticky bar renders only if isDirty || requiresApproval.
Inline edit primitive
Polymorphic — accepts type: "text" | "number" | "select" | "date". On enter editing, swaps display for input. Emits onCommit(value) on Enter/blur, onCancel() on Escape.
Activity source
Reads from new src/features/activity/get-activity.ts. Returns standard ActivityEntry[]: { id, when, kind, actor, summary }. Per-record query takes a filter: { entity: "booking", id: string }.
Where applied first
Phase 2.2 detail targets: dashboard/bookings/[id], dashboard/finance/statements/[id] (already exists — refactor onto template), dashboard/owners/[id], dashboard/villas/[id]. Dev OS: development-os/cabinets/qs/lines/[id], development-os/projects/[id].
