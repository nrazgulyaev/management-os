Finance · Owner statements

The single most-watched flow in Arconique. Every villa owner gets a monthly statement showing exactly how revenue became their payout: 17 line items across 7 categories, signed by Director, hash-stamped, settled within 5 days of month-end. Owners see a read-only mirror in their Portal.

Director · Accountant • monthly cadence
↓ Information architecture ↓ State machine ↓ Statements list ↓ Statement detail · 3 states ↓ Prepare flow ↓ Approve modal ↓ Payouts queue ↓ For Claude Code

Why this cabinet first

Owner statements ARE the product, from the owner's POV. A villa returns money once a month — that money is a statement. Bugs here destroy trust instantly. The flow has to be 100% transparent (every IDR traceable to a booking + receipt), 100% auditable (every approval hashed), 100% legible to a non-operator owner. This is also the only cabinet that touches three systems: Mgmt OS, Owner Portal (mirror), and Subscription billing (commission recognition).

Anatomy

Information architecture

The cabinet has 3 main routes + 1 read-only mirror route in Owner Portal. Two scheduled agents feed it.

Routes

Top-level: /dashboard/finance/*
Mirror: /owner/statements/*
  • /dashboard/finance/statements · List of all statements across owners + filter 2.2
  • /dashboard/finance/statements/[id] · Single statement detail · 3 states (draft / approved / settled) already exists, refactor
  • /dashboard/finance/payouts · Queue of bank-disbursement records (post-approval cashflow) 2.2
  • /owner/statements · Owner's own statements (read-only mirror) 2.3
  • /owner/statements/[id] · Owner's statement detail (same data, narrative chrome) 2.3

Agents involved

Live agents that produce data for this cabinet.
  • statement-preparer · Auto-drafts on the 1st of each month from ledger entries live
  • statement-anomaly-detector · Watches for line-item outliers (e.g. utility +20%, missing receipts) 2.2

Modals + flows

Cross-cabinet shared interactions.
  • <ApproveStatementModal> · ConfirmModal · shows hash + IBAN reveal · Director-only 2.2
  • <PrepareStatementModal> · Form-md · pick period + villa(s), kick off agent 2.2
  • <StatementLineEditModal> · Inline override (Accountant adjusts a line) 2.2
  • <SendToOwnerModal> · Confirm · sends PDF + email + unlocks Owner Portal view 2.2
Lifecycle

Statement state machine

List uses
<ListPage> + <FilterBar> + <BulkBar> + <PagerNumbered> + <SortableHeader> · all from Phase 2.1 primitives.
Detail uses
Template 05 assembly B (B1 + B3 + B8). <DetailPage> + <DetailHeader> + main panel (single big <Card padding="none" overflowHidden> with table.data) + <DetailActionBar>. No tabs, no side, no related.
State machine
New src/features/statements/state-machine.ts exports StatementStatus = "draft" | "draft_revised" | "approved" | "sent" | "settled" and transition helpers canApprove(s, role), canSend(s), canSettle(s), etc. Used by detail page to gate action bar buttons.
Schema
Existing tables (Phase 1 audit): statements (header + status + hash + actor IDs), statement_lines (line items keyed to statement_id + section enum + booking_id?/receipt_url? for traceability), payouts (one per approved statement, tracks wire status). Add statement_anomalies table (FK statement_id, kind enum, severity, ack_by).
Agents involved
statement-preparer · existing, agent code statement_preparer in registry. Triggered: scheduled (01 of month 06:00) OR manual via <PrepareStatementModal>.
statement-anomaly-detector · new, runs after each prepare. Writes to statement_anomalies.
Modals
<PrepareStatementModal> · form-md, lives in src/components/finance/prepare-modal.tsx
<ApproveStatementModal> · confirm-sm, in src/components/finance/approve-modal.tsx
<SendToOwnerModal> · confirm-sm, in src/components/finance/send-modal.tsx
<StatementLineEditModal> · form-md, opens when Accountant clicks ↗ on a line. Adds an override row to the line ledger (original line untouched, override delta tracked for audit). Future iteration.
Sec-pill component
New <SectionPill kind="revenue|fees|taxes|expenses|shared|mgmt|reserves"> · used inside table cells of the detail screen. Lives in src/components/finance/section-pill.tsx. Tones come from CSS, not from props.
CSS additions
Add .sec-pill + 7 tone modifiers to src/styles/components.css (Phase 2.0 modules). Scope [data-product].
Owner mirror
Same primitives. Detail page reads same data via different query (filtered by owner_id = current_user.owner_id). Read-only — no action bar. Renders narrative-flagged copy in EmptyState if no statements yet.
Telemetry
Emit statement_prepared · statement_approved · statement_anomaly_flagged · statement_sent · statement_settled. Powers SLA dashboards.
Test fixtures
Seed 5 statements per status (draft, draft_revised, approved, sent, settled). Include 1 with anomaly flagged for visual tests. Existing fixture in tests/fixtures/finance/ covers most — extend.
