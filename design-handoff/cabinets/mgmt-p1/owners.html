Owners

14 active owners across 41 villas. CRM-ish but specific to property ownership — Director tracks retention risk, payout history, portal engagement. Each owner record is the canonical handle for everything downstream: bookings of their villas, statements they receive, channel/marketing performance, and AI-detected anomalies (payout drift, occupancy regression).

Director · Account Mgr • quarterly + ad-hoc
↓ IA ↓ List ↓ Detail ↓ Onboard flow ↓ Retention risk ↓ For Claude Code

The hidden layer

Owners barely log in (2–4×/month). But everything an operator does in Mgmt OS ultimately changes their P&L. The list view is for Director's daily glance ("is anyone unhappy?"). The detail view is the source-of-truth record — contact info, commission terms, portal access, payout history, AI-flagged retention risk. Onboarding is once-per-owner but high-stakes (multi-step lg modal, IBAN handling).

Flow A · Onboard

Onboarding · 3-step lg modal

The most consequential setup in Arconique. Multi-step template 06 lg-form with explicit step indicator. Save-and-finish-later persists partial state — onboarding can take days for institutional owners. onboarding-doc-checker agent validates uploaded docs in real time on step 1.

Step 1 · Identity
Legal name · type (individual / trust / corp) · tax residency + ID number · primary contact (name/email/phone) · ID upload (passport or corp registry) · auto-validated by onboarding-doc-checker · sets identity_verified_at on success
Step 2 · Commission & payouts
Commission model (flat % · tiered · fixed) · default 18% per MSA · payout currency · payout method (Wise · SBI · DBS · wire) · IBAN/SWIFT/routing · encrypted at rest · visible only to Directors
Step 3 · Villas & portal
Link villas (typeahead from active portfolio · multi-select) · auto-pulls MSA dates from villa records · send Owner Portal invite (toggle, default on) · email preview · finalise creates owner record + emits owner_onboarded
Save & finish later
Persisted in onboarding_drafts table keyed by Director user_id · resume URL emailed · expires 14 days. Modal shows "Resume draft · Step 2 saved 3h ago" banner if active draft exists when triggering "+ Onboard owner".
Behavior on submit
1. Create owners row
2. Link villas (write to owner_villas junction)
3. Send portal invite if toggled
4. Schedule first statement reminder for next month
5. Tag owner: tier auto-derived from villa count + projected ARR
Validation gates
Block submit if: IBAN format invalid, ID doc rejected by checker, no villas linked, payout method incompatible with currency
Intel

Retention risk model

What makes the owner-intelligence agent fire. Three risk levels — Healthy / Watch / Flag — surfaced as pills in the list and as insight cards in the detail.

Signal 1 · Payout drift
MoM change in net payout. Watch at −10%, Flag at −20%. Compares to 3-month rolling avg, not single-month-prior, to avoid seasonality false-flags.
Signal 2 · Occupancy regression
YoY occupancy change for villa(s). Watch at −15%, Flag at −25%. Excludes Q1 (Bali low season).
Signal 3 · Portal disengagement
Days since last login. Watch if >30d, Flag if >90d AND last statement had any anomaly.
Signal 4 · Statement dispute
If owner has sent >= 2 statement-revision requests in last 3 months. Auto-Flag.
Signal 5 · Maintenance escalations
If >= 3 open maintenance tickets on owner's villas for >= 14 days. Watch.
Surfacing
Highest active signal → pill on list row
Active signals → insight card on detail with "Schedule call" / "Dismiss" actions
All-time signals → Activity tab timeline
Dismissal
Director can dismiss an insight with a reason ("Already addressed" / "False positive" / "Acknowledged"). Dismissal trains the model and suppresses re-fire for 30d unless signal intensifies.
Cadence
Daily scheduled run at 05:00. On-demand "Run intelligence scan" button on list re-runs immediately.
