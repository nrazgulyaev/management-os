03—Caution flow

Same audit chain as impersonate and suspend in cabinet 01: 2FA → reason → audit-log row stamped with actor + invoice id + Stripe refund id.

04—Policy

Dunning policy · what the runner executes

The dunning runner reads this configuration on every sweep. Steps fire in order; an earlier successful charge cancels later steps. The terminal step (suspend) is locked behind tech-lead approval — it can't auto-fire on Atelier-tier orgs even if reached. Stage chips on the triage queue (sec 01) map 1:1 to the day-numbered steps below.

05—Spec

Schema · agents · audit

Quick reference for the data-wiring PR. Most of this already exists from Phase 2 data-wiring's billing slice — what's new for cabinet 04 is the dunning policy table, the refund-audit relation, and the dunning-runner agent registration.

Tables · existing

invoices
org_id · stripe_invoice_id · amount · currency · status · issued_at · paid_at · due_at · period_start · period_end — already in main
payments
invoice_id · stripe_charge_id · attempt_no · status · decline_code · raw_reason · charged_at — already in main
refunds
invoice_id · stripe_refund_id · amount · mode (full/partial/credit) · reason_category · justification · actor_user_id · audit_log_id — already in main, justification col added Phase 2 data-wiring

Tables · new for 2.5

dunning_policy
id · scope (default · tier · org) · scope_id · steps_jsonb · effective_from · created_by · version — versioned, never deleted
dunning_runs
invoice_id · step_no · fired_at · channel · outcome (recovered/no_change/escalated) · agent_run_id
billing_audit
actor_user_id · org_id · action (refund · credit · manual_charge · policy_edit) · before · after · justification · ip · ts — feeds cabinet 07 audit log

Agents

dunning-runner
cron every 2h. Reads dunning_policy, walks failed invoices, fires the next due step. Caps at policy D+14 for non-Atelier; logs but never auto-suspends Atelier.
refund-audit-sealer
cron daily 02:00. Verifies every refunds row has matching billing_audit + Stripe refund id. Pages tech-lead on mismatch.
stripe-webhook-replayer
cron every 15m. Replays missed Stripe webhooks against payments. Already exists.

Caution-flow rules

refund
2FA required · amounts ≥ $50 single-actor · amounts < $50 require tech-lead approval (anti-mistake guard)
suspend
Inherits cabinet 01 flow. Triggered manually from triage row S4 OR escalated from dunning policy. Never agent-auto-fires.
policy edit
Versioned; previous version stays queryable. Audit-log entry on every save. Re-publishes to dunning-runner on next sweep.
