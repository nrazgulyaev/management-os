Owner P1 · 02

Statements · read-only mirror + sign-off

The owner's view of their own monthly statements. Same data as Mgmt Finance — different chrome, different actions, different voice. Owner cannot edit; Mgmt cannot see this view. Owner does one of three things: Acknowledge (most common), Dispute (rare, with reason), or do nothing for 14d → auto-acknowledged with audit trail.

Owner · read-only • monthly cadence
↓ IA ↓ Owner state machine ↓ Statement list ↓ Statement detail ↓ Sign-off modals ↓ Mobile ↓ For Claude Code

Voice differs · numbers don't

Numbers, line items, hashes are identical to Mgmt — same DB rows, no transformation. What changes: framing ("Your statement", "Your villa returned IDR 142.5M this month"), category labels (Mgmt-internal jargon like "PHR" stays but with hover-explainer for Owner), and most importantly the action surface: Mgmt = Approve / Send / Edit; Owner = Acknowledge / Dispute / Download.

  • <AcknowledgeStatementModal> · confirm-sm · default focus = primary (safe) 2.3
  • <DisputeStatementModal> · form-md · reason picker + free text + optional photo 2.3
  • <WhyThisNumberDrawer> · side-drawer · per-line explainer (e.g. "PHR is Bali hospitality tax, 10% statutory") 2.3

Cross-system

  • Owner action → emits event → Mgmt Finance sees status update in their list (owner_status column) — no manual sync.
  • Dispute → opens a thread in Mgmt Inbox (assigned to Director by default).
  • Auto-acknowledge after 14d → silent state transition; visible in audit log; no notification.

Cross-cabinet integration

Auto-ack at 14d → silent; visible in Mgmt audit log only.
