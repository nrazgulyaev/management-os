Personal-stay flow

Owner picks dates → submits request → Mgmt sees in Bookings cabinet (as a special booking type "owner_stay_request") → confirms (or counter-proposes) → owner sees confirmation in Inbox + this calendar. No revenue collected on owner-stay (line in Statement: "Owner stays · 0 IDR · 3 nights").

Routes

Multi-day events
Server pre-computes bookings[].dayStrip = {startCol, endCol, week} for fast render. Strip styling: rounded ends on start/end day, square middle.
Color encoding
Terra = guest booking · Gold = pending owner request · Green = confirmed owner stay · Cream-deep = empty turnover day
Request validation
Frontend: dates >= tomorrow, <= 12mo away. Server: no overlap with confirmed guest bookings (warn but allow — Mgmt arbitrates).
Cross-cabinet
Personal request creates booking row with kind=owner_stay · status=requested. Routes to Mgmt Bookings list (filtered tab "Owner requests"). Mgmt confirm → notifies owner via Inbox · auto-updates calendar event green.
Mobile
≤900px: month grid → compact week-strip + day-detail drawer (tap day → drawer slides up with that day's events). Pipeline list stays.
