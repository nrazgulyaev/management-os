List views are mostly straightforward; flow screens are where the design needs to commit.

3-way diff

Mobile patterns

Main view: stack the curve / rules / comps tabs as a top segmented control instead of three side panels. Default to Rules — the most common reason an owner opens pricing on mobile is to flip a rule on/off, not stare at the curve.

Top segment
Three-tab pill. Curve is read-only; Rules is the write surface; Comps is reference data.
Rule card
Name + signed delta. Body explains the condition in plain language. Tap-anywhere opens the editor. Paused rules are at 55% opacity, grouped below active.
Priority order
Long-press to reorder. Number-badge to right of the name shows priority. Higher number = lower priority (engine evaluates ascending).
4-step editor
Name & effect → Trigger → Scope → Review & commit. Each step ≤ 6 fields. Linear, no jump-back beyond the prev button.
Preview band
Accent-tinted card at the bottom of each step. Live-computed against today's data so the owner sees exactly what changes before committing.
Commit
Final step's primary CTA is Activate (or Save as draft). Activation fans out to all linked channels and shows a sync-status toast.

Mobile patterns

Today board is a triple list (arrivals / in-house / departures) — a classic mobile shape, no design innovation needed. The check-in FSM is the deliverable: linear 4 steps, each fits one screen, OCR-assisted, save-&-pause supported.

Today board
KPI strip across the top (4-up: arrive / in-house / depart / late). Three list sections below; each shows max 3 cards with "view all" if more.
Card badge
VIP / ID-pending / turn / late are coloured pills at the right side. Replaces desktop's hover-only metadata.
Check-in steps
01 Identity · 02 Stay · 03 Sign · 04 Handover. Same labels as desktop FSM. Stepper bar at top shows progress; current step pulses.
OCR assist
Step 01 opens with passport-scan affordance. Agent extracts fields and pre-fills — the staff verifies, doesn't type.
Save & pause
Every step has a left-side ghost button to bookmark the flow and return to it from the Today board ("3 in-progress"). The whole point of save-pause: staff can hand the phone to a colleague mid-flow.
Hit targets
Every interactive row is ≥ 48 px tall. Checkable rows have a 22 × 22 visual + 44 px row hit area.
Multi-adult
Dashed "+ add second adult" appends another identity sub-card to the same step. Each adult is independently scannable.

Mobile patterns

Inbox is a single vertical list grouped by status (Urgent · Open · Resolved). Urgent rows get a red border + 30-min escalation timer per the comp-policy spec. Thread view layers a comp-approval sheet on top of the conversation — the staff doesn't context-switch to a separate "offer comp" screen.

Urgent rule
Any request with escalated_at set and unresolved > 30 min gets a red badge + danger border. Pulse animation on the badge.
Avatar
Initials in the cream/sand circle — no actual photos for guests (privacy + agnostic to source).
Thread bubbles
Guest = neutral paper bubble (left). Staff = ink bubble (right). Agent = accent-tinted (left) — same channel as guest, so the guest sees "concierge" not "AI".
Agent suggestions
Bold names in agent messages are tappable — opens a sub-sheet with the venue's detail and direct-book affordance.
Comp sheet
Bottom sheet, pre-filled with a suggested amount based on the request context. Policy line shows green pill within or amber requires approval based on the 500k threshold.
Above threshold
If amount > 500k, the policy pill flips to amber "requires approval", primary CTA changes to Request approval →, and a manager dropdown appears.
Adjust amount
Numeric pad sub-sheet. Live-updates the policy pill so the staff sees when they cross the threshold.

Mobile patterns

Storyboard scroll mirrors the primitive (sticky day-header, vertical photo feed). The capture flow is the marquee mobile screen — camera fills most of the screen, voice records while shooting, agent transcribes in the background, GPS + weather auto-attach.

FAB
56 × 56 px floating button, bottom-right, above tab bar. Project context is inherited from the storyboard the user is viewing.
Camera-first
Step 1 opens straight into the camera. No "give the app camera permission" interstitial after first grant.
Voice-while-shooting
Recording starts when the shutter is pressed; stops when the user taps the waveform. The transcript becomes the default caption.
Auto-tags
Pre-filled chips below the caption: project, area inferred from GPS, work-type guessed from photo content. Tap to remove, "+ tag" to add custom.
Auto-metadata
GPS + weather are fetched silently and shown as small confirm lines. User sees what the system captured; can override.
Incident flag
Single-tap escalation. Opens a sub-sheet to set severity + assignee. Saving the frame creates the linked incident row.
3-step total
01 capture · 02 caption + tags · 03 submit. Most frames complete in < 60 sec.

Mobile patterns

Buyer detail compresses to a single vertical scroll: name + chips, mini-pipeline strip, key fields, recent activity. Offer modal pre-fills from the buyer record — the salesperson tweaks tranches and conditions, hits send.

Mini-pipeline
6-segment bar at the top of detail. Current stage in accent, completed in ink, pending in muted. Below it: stage labels. Replaces the desktop full Kanban context.
Detail fields
Key-value rows for the 6 most-used fields (expected, unit, channel, owner, last touch, next action). Tap any row → field editor sheet.
Recent activity
Last 2-3 log entries inline. "View all" expands to a full timeline.
Offer modal · ladder
Each tranche is a row with a numbered circle (done / current / pending), label, trigger, amount. Tap a row → tranche editor sheet (amount, % or absolute, trigger date or milestone).
Add tranche
Dashed row at the bottom. Newly-added tranches insert before the current "current" row to keep the ladder ordered.
Conditions
Checkable list of policy clauses. Defaults pre-checked based on buyer status.
Send as PDF
Generates the canonical offer PDF and shares via system share sheet (WhatsApp, email, etc.). Also logs the send event onto the buyer's timeline.

Mobile patterns

LP positions table reflows to one row per LP with name + country on the left, amount + MOIC on the right. The mobile sort is MOIC-desc by default — that's the question the GP usually has. Capital call detail keeps the inverted ink-card summary (works at any width) and stacks allocations as a single column.

KPI strip
3-up: committed / called / DPI. MOIC isn't in the strip — it's per-LP in the table.
Sub-tabs
LPs / Calls / Distributions. Default LPs; tapping Calls/Distributions opens corresponding lists.
LP row
Two columns: identity (name + country/type) and figures (commitment + MOIC). Tap a row → LP detail screen with positions, distributions history, contact, docs.
Overflow row
"+ 8 more LPs" with aggregated commitment + MOIC range. Tap to expand to full list (separately paginated).
Capital call total
Big inverted ink card: total called + due date + received/pending split. The most-asked-about number is at the top, not buried in a table.
Allocation status
Coloured dot before each LP name: ok / pending / overdue. Three-bullet strip above the list shows aggregate counts.
Overdue card
If >= 1 LP overdue, accent-tinted block at the bottom with the offender's name + days late + last-reminder date. Single CTA → send escalation reminder. Replaces desktop "audit" tab.
Export PDF
Ghost CTA. Generates a per-LP statement bundle (one PDF per LP, zipped) and offers via share sheet.
