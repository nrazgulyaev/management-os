The artboards below are the audit deliverable — copy the mobile-specific CSS into src/styles/components-2.4.css and the React components gain a .mobile-suffixed variant or an internal viewport hook.

01 · Channels

One villa, channels stacked, days as columns.

Desktop's two-axis matrix collapses to one villa per view. A villa-switcher above the grid takes over what was the left-column hierarchy. Days slide horizontally inside the grid container — the user pages through 3-day windows instead of zooming.

Default window
3-day. Wider windows (7d, 14d) require horizontal scroll inside the grid; the segmented control above sets the column count.
Villa hierarchy
One villa at a time. The header row's villa-name button opens a bottom sheet with the villa list (grouped by region). Switching scrolls the grid back to today.
Hit target
Cells are 72 × 48 px (was 56 × 44 on desktop). Below 44 px tall the inline-edit popover stops feeling tappable.
Edit affordance
Tap a cell → full-width bottom sheet with the rate input + channel name + last-pushed timestamp. The hover-only desktop inline popover doesn't have a mobile equivalent — sheet is the right primitive.
Stay overlays
Multi-day stay pills are dropped from the mobile view; the underlying cell takes the .booked state instead. Tap the cell → stay detail.
Conflict signal
Same dot indicator as desktop (top-right of cell). Tapping a .conflict cell jumps straight to the 3-way resolver — no intermediate hover state to traverse.
Recent strip
Below the grid, last 10 sync events as a vertical list. Replaces the desktop legend (legend moves to a small "?" affordance on the topbar).
Owner palette
Mgmt and Owner share the cream palette — no separate variant needed.

02 · Dynamic pricing

Curve stays charted, edit moves to a bottom dock.

Desktop's 900-wide curve compresses to ~330 with one less pixel of vertical room. The interaction model survives because the handle hit target is decoupled from the visual handle size — touching anywhere within 22 px of a handle selects it, then a bottom dock takes over the edit surface (rather than a tooltip pinned to the cursor).

Default window
14d on mobile (not 90). The forward view shows fewer days more legibly. Tap "14d" segment in the topbar to step to 30d / 60d / 90d with horizontal scroll inside the SVG.
Today marker
Vertical dashed terra line at x = today. Anchors the user when scrubbing.
Handles
Visual radius 6 px, hit radius 22 px. Selected handle pops to radius 8 + solid fill. Drag-to-edit is dropped — the bottom dock replaces it. Mobile users tap a handle to select, then nudge with ±buttons or type a number.
Bottom edit dock
Sticky to the screen bottom while a handle is selected. Shows date, current value, delta vs algo, revert + commit. Dismisses on tap-outside or commit.
Overlay pills
Horizontal-scroll chips above the chart. Replaces desktop legend. Tap to toggle a line on/off — same toggle as desktop knobs.
Rules-in-play
Inline below the chart instead of as a side panel. Three to five visible, "see all" expands to a sheet.
Annotations
Event markers (holidays, conferences) collapse to small · dots on the X-axis. Tap → bottom sheet listing every annotation in the visible window.

03 · Site supervisor

The format that was already a feed.

The desktop 2-column layout (sticky day-meta on the left, scrollable frame column on the right) folds cleanly into a single vertical scroll. The day-meta becomes a sticky header bar at the top of each day's frames; the side-metadata card becomes a compact strip beneath the caption.

Day header
Sticky to the top of the scroll. Shows date glyph, day-of-week, foreman name, weather. Stays visible while the user reads through that day's frames.
Frame photo
Full-bleed within the screen padding. Preserves the desktop aspect-ratio variants: 16:9 default, 4:5 tall, 21:9 wide. The wide variant is rare on mobile — usually downgraded to 16:9 to keep the caption above the fold.
Photo pills
Top-left tag (block name, work-type) and bottom-right timestamp — same as desktop. Alert pills (incident, flag) keep the red/amber tones. Tap a photo → fullscreen view.
Caption + narration
Caption uses the display serif at 16 px; narration drops to 13 px sans. Side metadata becomes an inline strip (crew / m³ / supplier / etc.).
Capture button
Not shown in this artboard, but the foreman's "capture frame" entrypoint is a floating + FAB above the tab bar (bottom-right, 56 × 56 px). Tapping it opens the camera-first capture-flow.
Voice clips
If a frame has a voice note, a small play-button row appears above the caption. Tapping starts inline playback — no fullscreen needed.

04 · Sales pipeline

Lane-as-screen, stages-as-tabs.

Desktop's 5-lane Kanban can't survive at 360 px without forcing each card below 60 px wide. Instead, mobile shows one lane at a time, full screen width, with the stage strip across the top serving as both navigation and at-a-glance pipeline health. Horizontal swipe between lanes feels native; tapping a stage chip jumps directly.

Stage strip
Horizontal-scroll chips. Active lane is inverted (ink fill). Each chip shows a count badge — at-a-glance funnel shape.
Lane head
Display serif name + aggregate value strip. No "add lead" button at the top — the FAB handles new-lead creation.
Cards
Reuse the desktop card layout almost verbatim (it was already vertical and ~280 px). Drag-to-reorder within a lane is preserved; cross-lane drag is replaced by a long-press menu (move to →).
Swipe between lanes
Horizontal swipe on the cards area pages to the prev / next lane. The hint strip ("swipe ← X | Y → swipe") is dropped after first three sessions per user.
Drag affordance on cards
Desktop's cursor:grab is meaningless. Replace with a 6 × 24 px drag handle on the right side of each card, only revealed when the lane enters reorder mode (long-press anywhere).
Filters
Top-right of the topbar — same as desktop. Filters apply across all lanes, count badges in the stage strip update live.
Won/Lost
Won is the rightmost regular lane. Lost is hidden by default; a small "+ Lost (12)" chip appears at the end of the stage strip when there are lost deals in scope.

05 · Investors

Pivot 90° — vertical cascade, bars track magnitude.

Desktop's horizontal waterfall packs 7 bars into 900 px and uses connecting dashed lines to show carry-forward. At 360 px there's no room for that geometry. Mobile pivots the chart 90° — each step is a row, with name + sub-label on the left, signed value on the right, and a bar fill that encodes magnitude (proportional to gross proceeds).

Row geometry
Two-line top (name + value), one-line bar. Total row height ~52 px including bottom padding. Subtotal/total rows use the ink fill; add steps use ok-green; deduct steps use danger-red.
Bar position
For add / sub steps the bar can be offset left (e.g. margin-left: 92%) so its visual end-point shows the carry-forward total at that step — visually it still reads as a cascade.
Subtotal emphasis
Subtotal rows ("Distributable", "LP distribution") use bolder name + ink bar — same visual weight as desktop's "total" bar variant.
Footer KPIs
4-up grid: MOIC, IRR, GP carry, hold years. MOIC uses accent colour (it's the headline metric). Same as desktop.
Interactivity
Each row is tappable → bottom sheet with the calculation breakdown (which params drove this step, which LPs are affected). Replaces desktop's hover tooltips.
Sharing
Long-press the chart → "share as image" generates a 1:1 social image (square, ink bg, light text). Useful when GP forwards distribution proof to an LP.
Tabbed scenarios
Above the chart on real pages: tabs for "actual" vs "model A" vs "model B" — same as desktop. Each tab swaps the data, rows re-render with a 200ms ease.
