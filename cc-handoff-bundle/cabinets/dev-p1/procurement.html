Procurement + Vendors

Buying side of construction. Procurement Manager issues RFQs (Request for Quotation) to 2-4 vendors per BOQ line group, compares quotes side-by-side, awards POs (Purchase Orders), tracks delivery + invoice + payment. Vendors get scored over time on price + reliability + quality. Feeds into BOQ actuals + CFO cashflow.

Procurement Mgr · QS read · CFO read • cycle 7–21d per RFQ
↓ IA ↓ RFQ list ↓ Quote comparison ↓ Vendor scorecard ↓ For Claude Code

The procurement loop

BOQ line needs material → Procurement creates RFQ → invites 2-4 vendors → vendors submit quotes → side-by-side comparison → award PO to one → vendor delivers + invoices → invoice cost-coded back to BOQ line as actual → variance triggers if Δ > 5% → QS reviews. 7 stops, ~14 days end-to-end. This cabinet runs the first 5.

Screen 3

Vendor scorecard · /development-os/vendors/[id]

Score composite: price competitiveness (40%) · on-time delivery (30%) · quality / QS-acceptance rate (20%) · responsiveness (10%). Refreshed nightly. Visible in RFQ comparison + Vendor directory list.

Composite score
0–100 scale. Updated nightly by vendor-score-updater. Formula weights documented in src/features/vendors/scoring.ts.
Price competitiveness
For each completed RFQ vendor participated in: (winner_total / vendor_total) × 100. Vendor's avg across their last 20 RFQs.
On-time delivery
For each PO: (planned_lead_time / actual_lead_time) × 100, capped 100. Avg across last 20 POs.
Quality · QS acceptance
% of variance reviews on this vendor's POs that resulted in QS-approve (not reject/investigate). Last 90d.
Responsiveness
Time from RFQ-sent to first-quote-received. Avg across last 10 RFQs. Lower is better; normalized 0-100.
