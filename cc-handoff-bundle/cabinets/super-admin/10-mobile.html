Phase 2.5 · cabinet 10 · mobile pass

Mobile · the phone version of the control room.

Super-admin on mobile isn't "do everything from your phone" — it's "act quickly when an alert wakes you up". 18 mobile artboards across all 9 cabinets, focused on the screens an operator actually opens away from the desk: status overview, triage queues, support replies, kill-switches, audit skim. Heavy admin work (plan editor, dunning policy editor, flag override matrix) stays desktop-only.

principle 01

One action per screen

Mobile screens are designed around the single action an operator came for. Approve / kill / reply / acknowledge. No multi-step wizards on phone.

principle 02

2FA-gated still 2FA-gated

Caution actions (impersonate, suspend, refund, kill-switch, agent-kill) require 2FA on phone too — usually faster via biometric, but never bypassed.

principle 03

Read-mostly defaults

Default landing for any cabinet on mobile is the most-recent / most-urgent view. List + drill-in. Filter pickers are bottom-sheets, not new screens.

01—Organizations

List · detail · impersonate sheet

Sales uses this away from the desk: scan the list for "needs attention", tap into an org, decide. Impersonate stays a caution-bordered bottom-sheet (mode picker + reason + 2FA), never a full new screen — operator's already deep in the org context.
