03—Implementation

Schema · gates · feature-flag bridge

Schema

plans
✅ exists · 0085_subscription_plans
plan_versions
🟡 partial · v-col exists, no separate version table — add for "stay on v2.1 vs migrate to v2.2" semantics
plan_prices
🔴 new · one row per (plan_id, version, currency, cycle) — supports multi-currency variants
plan_limits
🔴 new · key-value pairs per (plan_id, version)
plan_features
🔴 new · feature_key → enabled per (plan_id, version). Bridge to Feature flags cabinet (05).
trials
✅ exists (via subscriptions.trial_ends_at) · the table here just visualises the column

Endpoints

POST /api/super-admin/plans
🔴 new · creates next-version + plan_prices/limits/features in one txn
POST /api/super-admin/plans/:id/migrate-subscribers
🔴 new · gated · 2FA · moves all subscribers from old version to new
POST /api/super-admin/trials/:orgId/extend
🔴 new · 1×, max 7 extra days, audited
GET /api/super-admin/plans/conv-signal
🔴 new · computes the trial conversion-signal heuristic (villas added × users active × days into trial)

Agents

trial-conversion-scorer
🔴 new · daily · writes conv_signal per trial org → high/medium/low/stalled
trial-extension-recommender
🔴 new · on trial day 12 · flags candidates where Sales should reach out before auto-expire
plan-fit-detector
🔴 new · daily · per active org · flags upgrade candidates (consistently near limit) and downgrade candidates (consistently under-utilising)

Gates & bridges

feature-flag bridge
plan_features → cabinet 05 (Feature flags) consumes as the per-plan baseline. Per-org overrides layer on top.
billing bridge
plan_prices ↔ cabinet 04 (Billing) reads the price-per-cycle to compute the invoice amount.
2FA gate
Migrate-all + currency-add require 2FA. Editing limits + features within current version doesn't.
