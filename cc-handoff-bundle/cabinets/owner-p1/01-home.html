Tonality anchor

This screen sets the voice for all 7 Owner cabinets. Newsreader display at 48px for greeting, 36px for hero amounts, 18px for body context. Big numbers as headlines (not in tiles). Editorial flow — owner reads top-to-bottom on first visit, then becomes muscle-memory jumping to specific cabinets. No KPI grid of small numbers — that's Mgmt's job. Where this lands

Route
src/app/(owner-portal)/owner/page.tsx · single page, server-rendered with owner data
Primitives
<OwnerGreeting name today /> · big greeting + narrative
<HeroTile variant="dark"|"flat" label value sub foot? /> · used in 3-up hero
<VillaCard villa orientation="row"|"col" /> · also used in /owner/villas list
<UpcomingList rows /> · simplified booking list for next 14d
<QuickActionGrid actions /> · 4-up card grid
Data fetching
One server query: getOwnerHome(currentUser.owner_id) returns { ytdNet, pendingStatement?, nextStatementDate, villas, upcoming, recentActivity } · cached 5min per owner.
Pending statement card
Only renders when owner_state === "pending" on at least one statement. If multiple pending — shows count, links to list. Gold-tinted border + soft shadow.
Mobile breakpoint
≤900px: hero tiles stack vertically; villa card switches to col orientation; upcoming list shrinks to 1-line per row; quick-actions become 2-col grid.
Cross-cabinet links
"Review statement" CTA → /owner/statements/[id]. "Full calendar" → /owner/calendar. "All villas" → /owner/villas. Quick actions deep-link into respective flows (personal stay → Calendar with stay-form open; message → Inbox compose; Q-review → Settings/calendar-of-Director).
Telemetry
owner_home_viewed · owner_quick_action_clicked · owner_pending_statement_cta_clicked
NOT here
Tax statements summary (Documents cabinet) · Mgmt team contact directory (Inbox header) · billing/subscription (Settings)
