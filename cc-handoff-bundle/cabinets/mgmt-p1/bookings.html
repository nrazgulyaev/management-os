Bookings

The operational heart. ~250 bookings live at any time across 41 villas, syncing from 4 channels (Airbnb, Booking.com, Agoda, Direct) + 1 travel-agent intake. Operators triage today's arrivals, handle ad-hoc edits (extensions, refunds), and feed downstream cabinets — every booking row eventually becomes a line in Finance/Statements.

Flow A · Create

New booking · scaffold from Phase 2.1

Already implemented (PR 3 proof-of-life). This section locks the final field set — 7 fields total, not 5 like the proof-of-life. Adds: party size + currency override (rare, but Director-required for high-value bookings).

Field 1 · Villa
villa_id · select from active portfolio · required · pre-fill from route context if /villas/[id]/new
Field 2 · Check-in
checkin_at · datetime · required · default 14:00 local · validates against villa calendar (no double-book)
Field 3 · Check-out
checkout_at · datetime · required · default 11:00 local · derives nights for nightly-rate calc
Field 4 · Primary guest
guest_name + guest_email + guest_phone · email required (for Owner Portal mirror), phone optional
Field 5 · Party size
pax_adults + pax_children · numeric · required · validates against villa.max_pax
Field 6 · Channel
channel · enum · required · default Direct · drives commission calc in Finance
Field 7 · Internal notes
internal_notes · textarea · optional · visible to ops only, not in guest folio
Behavior
Submitting creates booking + emits booking_created event · triggers arrival-prep agent if check-in <= 7d away · adds to today-strip if check-in in this week
Validation gates
Block submission if: villa unavailable (calendar conflict), pax exceeds max, check-out before check-in
Flow B · Cancel

Cancel booking · refund flow

Destructive · sm-confirm. Lock fields based on cancellation policy: full refund (>14d), 50% (7–14d), 0% (<7d) — but Director can override. Shows real refund amount + reverse-channel.

Trigger
Bulk action "Cancel" on list · or "Cancel booking" on detail header
Modal size
sm-destructive · default focus = Keep booking (outlined accent)
Auto-computed
Refund amount based on policy + days-to-arrival · displayed as IDR + USD
Channel reverse path (Airbnb auto-refund · Stripe partial-refund · Direct wire)
Director override
Checkbox: "Override policy refund amount" reveals editable IDR input · logs override in audit
Guest notification
Checkbox (default on): "Notify guest with reason" · opens compose modal with pre-filled template
Side-effects on confirm
1. Updates booking.status = cancelled
2. Emits booking_cancelled event
3. Calls channel API to reverse charge
4. Adjusts statement preview for owner (next monthly cycle)
5. Frees villa calendar for re-book
6. Drops from today-strip + KPIs

Today strip
New <ArrivalCalendar> in src/components/bookings/arrival-calendar.tsx. 7-day horizontal grid. Visible only when filter view = "This week" OR no filter. Click day → applies date chip filter.
Channel pill
New <ChannelPill kind> in src/components/bookings/channel-pill.tsx. Tones: airbnb / bcom / agoda / direct / ta. Match brand colors.
Row-tone helper
New util src/features/bookings/row-tone.ts · getRowTone(booking): "arriving" | "departing" | "instay" | "cancelled" | undefined · applies .row-{tone} class to <tr>. Logic: today's date vs check-in/out, status.

Spec'd above. Stay details card + Charges card + Related strip.
Tabs · Charges
Same charges table from Overview but fullwidth + AddCharge button in header + per-row refund action. Each line links to /[id]/charges/[chargeId] for refund detail.

Primary guest + secondary guests · ID upload + special-requirement notes (dietary, mobility)

Cancellation policy
New src/features/bookings/cancellation-policy.ts · pure fn computeRefund(booking, today): {amount, channel, reason}. Default rules: >14d full, 7–14d 50%, <7d 0%. Director can override.

Agents
