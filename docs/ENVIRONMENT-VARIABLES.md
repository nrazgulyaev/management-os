# Environment Variables — Arconique Management OS

This document is the canonical list of every env var the Management
OS reads.  It is generated by hand but kept in sync with
`src/lib/env/registry.ts` — the test suite asserts that every
registry entry appears here.

## Quick start

```bash
cp .env.example .env.local
# fill in DATABASE_URL, DIRECT_URL, NEXT_PUBLIC_SUPABASE_URL,
# NEXT_PUBLIC_SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY at minimum.
npm run check:env
```

Run `npm run check:env --mode=production` before deploying to verify
the config will pass production gates.

## Categories

### Core app

| Var | Required | Purpose |
|---|---|---|
| `NODE_ENV` | always (set by platform) | `development` / `production` / `test`. |
| `NEXT_PUBLIC_APP_ENV` | production | App-level label (`development` / `staging` / `production` / `demo`).  Surfaces on `/dashboard/system/deployment`. |
| `APP_BASE_URL` | production | Canonical absolute URL for the deployed app, no trailing slash.  Used by Supabase Auth redirects, statement PDF links, cron handlers, notification CTAs. |
| `DATABASE_URL` | production | Pooled Postgres connection string. |
| `DIRECT_URL` | optional | Direct (unpooled) Postgres URL.  `scripts/migrate.ts` + `scripts/seed.ts` prefer this. |
| `CRON_MAX_CONCURRENT_PER_JOB` | optional | Default `1`.  Always 1 with current `job_locks` model. |

### Observability (Task H — all optional; missing = local-stdout only)

| Var | Required | Purpose |
|---|---|---|
| `SENTRY_DSN` | optional | Sentry DSN.  When set, the structured logger forwards `warn`/`error` lines to Sentry.  Unset = no external error forwarding. |
| `LOGTAIL_TOKEN` | optional | Logtail (Better Stack) source token.  When set, `warn`/`error` lines ship to Logtail.  Override the ingest host with `LOGTAIL_INGEST_HOST`. |
| `HEALTH_STALE_JOB_MINUTES` | optional | Default `60`.  Minutes a `job_run` may sit `running` before `/api/cron/health` reports it stale (returns 503). |

### Supabase

| Var | Required | Purpose |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | production | Supabase project URL. |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | production | Anon key (RLS-bound). |
| `SUPABASE_SERVICE_ROLE_KEY` | production | Service role key — server-only, bypasses RLS.  **MUST never appear in NEXT_PUBLIC_*.** |

### Security

| Var | Required | Purpose |
|---|---|---|
| `CRON_SECRET` | production | Bearer secret required by every `/api/cron/*` route. ≥ 32 chars. |
| `SECURITY_ENCRYPTION_SECRET` | production | Wraps MFA TOTP secrets at rest with AES-256-GCM. ≥ 32 chars. |
| `STAY_LINK_KMS_SECRET` | production | Wraps Wi-Fi passwords + verification links at rest. ≥ 32 chars. |
| `MFA_ISSUER` | optional | otpauth:// issuer label. Default `Arconique`. |
| `LOGIN_THROTTLE_ENABLED` | optional | `1` enables throttling.  Default `1`. |
| `LOGIN_MAX_FAILED_PER_EMAIL` | optional | Per-email failure threshold.  Default `5`. |
| `LOGIN_MAX_FAILED_PER_IP` | optional | Per-IP failure threshold.  Default `20`. |
| `LOGIN_LOCK_MINUTES` | optional | Lock duration when threshold exceeded.  Default `15`. |

### Notifications

| Var | Required | Purpose |
|---|---|---|
| `NOTIFICATIONS_DRY_RUN` | production (explicit) | `1` = never call providers; `0` = deliver.  MUST be set in production — env validator fails fatal otherwise. |
| `RESEND_API_KEY` | conditional (`NOTIFICATIONS_DRY_RUN=0`) | Resend API key. |
| `RESEND_FROM_EMAIL` | conditional (`NOTIFICATIONS_DRY_RUN=0`) | Verified Resend sender. |
| `TWILIO_ACCOUNT_SID` | optional | Twilio account SID. |
| `TWILIO_AUTH_TOKEN` | optional | Twilio auth token. |
| `TWILIO_FROM_SMS` | optional | E.164 sender number. |
| `TWILIO_FROM_WHATSAPP` | optional | `whatsapp:+...` sender. |

### AI

| Var | Required | Purpose |
|---|---|---|
| `AI_DRY_RUN` | production (explicit) | `1` = never call Anthropic; `0` = live.  Default `1` if missing. |
| `ANTHROPIC_API_KEY` | conditional (`AI_DRY_RUN=0`) | Anthropic key. |
| `ANTHROPIC_MODEL` | optional | Default `claude-3-5-haiku-latest`. |

### Demo / dev / bootstrap

| Var | Required | Purpose |
|---|---|---|
| `ARCONIQUE_FORCE_MOCK` | optional | `1` forces mock data.  **Must NOT be enabled in production** — env validator fails fatal. |
| `NEXT_PUBLIC_ENABLE_DEMO_MODE` | optional | Public demo banner toggle.  Allowed in `staging`/`demo`; flagged in `production`. |
| `ADMIN_BOOTSTRAP_SECRET` | optional | Required by `/setup/admin-bootstrap`. ≥ 16 chars.  Generate with `openssl rand -hex 32`. |
| `BACKUP_RUNBOOK_URL` | optional | Public link to the team's backup runbook.  Surfaces on `/dashboard/system/health`. |

## Validation behaviour

The validator in `src/lib/env/validation.ts`:

- In `development` / `test`: missing production-required vars produce
  warnings only.
- In `staging` / `production`: missing required vars produce fatal
  errors.  Weak secrets (placeholder values, < 16 chars) produce
  fatal errors.  Demo flags in production produce fatal errors
  (`ARCONIQUE_FORCE_MOCK=1`) or warnings (`NEXT_PUBLIC_ENABLE_DEMO_MODE=1`).
- Conditional vars (`RESEND_API_KEY` etc.) are evaluated against
  their gate (`NOTIFICATIONS_DRY_RUN=0`).
- Service-role-style names in `NEXT_PUBLIC_*` always fail fatal.

`getEnvReadinessReport()` returns the structured result;
`/dashboard/system/deployment` renders it.  `redactEnvValue()`
ensures no raw secret is echoed back — only the first 4 + last 2
chars of any non-public value.

## Adding a new env var

1. Add an entry to `ENV_REGISTRY` in `src/lib/env/registry.ts`.
2. Add a row to the appropriate category table above.
3. Add it to `.env.example` with a placeholder + comment.
4. If it's optional with a default, add a getter to `src/lib/env.ts`.
5. Run `npm run check:env` to verify the validator picks it up.

## Registry-vs-source audit (RELIABILITY-1 Task 5)

`npm run audit:env` scans every `.ts` / `.tsx` file under `src/` for
`process.env.X` references and diffs the set against this registry.
As of RELIABILITY-1's first run:

- **62 env vars** referenced in source code
- **32 entries** in the registry (`src/lib/env/registry.ts`)
- **31 vars used in source but missing from the registry** — these
  are blind spots for `check:env` (the validator can't warn when
  they're misconfigured) and silent-degradation hazards
- **1 retired entry** in the registry with no current source reference

The 31 missing vars span several feature areas:

| Area | Missing vars |
|---|---|
| AI providers | `OPENAI_API_KEY`, `OPENAI_MODEL`, `GEMINI_API_KEY`, `GEMINI_MODEL`, `AI_PROVIDER` |

| WhatsApp / Twilio | `WHATSAPP_PROVIDER`, `WHATSAPP_REQUIRE_REAL_PROVIDER`, `WHATSAPP_WEBHOOK_VERIFY_TOKEN`, `TWILIO_WHATSAPP_FROM_NUMBER` |

Recommended follow-up: a focused "env registry backfill" sprint to
add each of these to `ENV_REGISTRY` with the correct category +
required/optional level + redaction policy. Mechanical work, no
behavior change to the running app, but every backfilled entry
becomes a `check:env` gate that catches misconfiguration before
the operator hits it in production.
